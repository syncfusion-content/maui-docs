# Syncfusion A2UI Overview

The [Syncfusion A2UI for .NET MAUI package]() bridges the [A2UI v0.9](https://a2ui.org/specification/v0.9-a2ui/) agent-to-UI protocol with Syncfusion's cross-platform .NET MAUI control suite. It enables AI agents to generate interactive user interfaces using structured UI messages instead of raw markup or plain text responses.

Using Syncfusion A2UI, applications can transform agent responses into interactive UI elements such as **DataGrid**, **Chart**, **Scheduler**, and other business-oriented experiences. The generated interfaces are rendered using Syncfusion .NET MAUI controls, providing a native experience across Android, iOS, macOS, and Windows platforms.

The solution is built on top of the framework-agnostic `Syncfusion.A2UI.Core` runtime and includes a .NET MAUI-specific rendering layer that converts A2UI messages into visual components.

In short, Syncfusion A2UI for .NET MAUI allows AI-powered applications to dynamically generate and render rich user interfaces using Syncfusion controls without requiring developers to manually create those interfaces.

N> Syncfusion A2UI for .NET MAUI is currently available as a preview release. While the **A2UI v0.9 wire format** is stable, APIs, component coverage, and related tooling may evolve before the first stable release.

## Prerequisites

Before using Syncfusion A2UI for .NET MAUI, ensure you have:

- A .NET MAUI application targeting supported platforms.
- .NET 8 or later.
- Required Syncfusion .NET MAUI control packages for the components expected to be rendered by the agent.
- An A2UI v0.9-compatible agent capable of generating A2UI messages.
- A registered Syncfusion license key.

## What problem does it solve?

Traditional AI applications often return information as plain text, even when the user expects an interactive experience.

For example:

- A user asking *“Show me last quarter's sales by region”* expects an interactive chart instead of a textual summary or a generated table.
- A user who asks *“Schedule a meeting with the design team next Tuesday”* expects a calendar picker, not a confirmation string.

A2UI addresses this challenge by enabling AI agents to describe user interfaces through a standardized protocol. Syncfusion A2UI for .NET MAUI renders those descriptions as fully interactive controls, allowing users to interact with data and workflows directly within the application.

## Core concepts

Before diving into the end-to-end workflow, here are the terms used throughout this documentation.

- **Agent**: An AI system that processes user requests and generates A2UI messages describing the required user interface.
- `MessageProcessor`: A platform-independent runtime (`Syncfusion.A2UI.Core`) that processes A2UI messages, manages UI state, supports data binding, and maintains surface information.
- `SurfaceModel`: A logical user interface area generated by an AI agent. A surface contains one or more UI components that are rendered together.
- **DataModel**: A reactive data store that maintains values used by generated UI elements and keeps the interface synchronized with application data.
- **Catalog**: A registry that maps A2UI component definitions (for example, **DataGrid**, **Chart**) to corresponding .NET MAUI renderers and Syncfusion controls.
- **Actions**: User interactions generated from rendered components and sent back to the agent, enabling bidirectional communication between the user interface and the AI system.

## How it works

The following workflow illustrates a typical Syncfusion A2UI interaction:

1. A user submits a request to an AI agent.
2. The agent generates A2UI messages describing the required user interface.
3. The A2UI runtime processes and validates the messages.
4. A UI surface is created and rendered using Syncfusion .NET MAUI controls.
5. The user interacts with the generated interface.
6. User actions are forwarded back to the agent.
7. The agent responds with updated UI or data, and the interface updates automatically.

This cycle continues as long as the user interface remains active.

## Architecture

The solution is organized into multiple layers:

| Layer | Purpose |
|---------|---------|
| A2UI Protocol Layer | Defines the A2UI message structure and communication model. |
| Syncfusion.A2UI.Core | Processes messages, manages state, validation, and data binding. |
| .NET MAUI Renderer | Converts A2UI components into .NET MAUI visual elements. |
| Syncfusion Controls | Provides production-ready UI components rendered inside the application. |

This layered architecture allows the protocol engine to remain reusable while the rendering layer stays optimized for .NET MAUI applications.

## When to use it

Use [Syncfusion A2UI for .NET MAUI]() when:

- You want AI agents to generate interactive interfaces instead of text-only responses.
- Your application uses Syncfusion .NET MAUI controls.
- You need dynamic data presentation through charts, grids, forms, or schedulers.
- You want a standardized protocol between AI systems and user interfaces.
- You require two-way interaction between users and AI-generated experiences.

## When not to use it

Syncfusion A2UI for .NET MAUI may not be suitable when:

- The AI system does not support the A2UI protocol.
- Complete manual control over every UI element is required.
- The application does not require dynamic or AI-generated interfaces.
- Static screens provide a better solution than agent-driven experiences.
