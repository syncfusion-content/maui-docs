Each configuration is generated by the CLI with its restore/build path enabled,
then built again with warnings treated as errors. Its executable must display
an application window with the expected title within 30 seconds and remain
running for two more seconds. Validation then terminates that owned process.

This includes actual legacy Visual Studio MSBuild and Windows App SDK builds.
It is not a mocked build or a restore-only claim. Linux cross-compilation also
passed WPF/WinForms C#/VB .NET 8/9/10 and representative theme/control selections;
WinUI restore passed all three targets with each sample selection on Linux.

## Failures found and corrected

- VB WPF must use `Application.xaml` so the SDK treats it as an application
  definition. Using `App.xaml` produced an IComponentConnector compile failure.
- Classic VB projects need OptionInfer enabled; otherwise inferred local types
  cause warnings/errors under warnings-as-errors validation.
- A 10-second launch deadline intermittently rejected first WPF launches.
  The check now allows 30 seconds, requires the real application title and
  verifies continued execution after the window appears.

## Limits

These are native-window launch smoke checks. They do not compare screenshots,
exercise every Chart/DataGrid interaction, or establish exact visual theme
colors, accessibility or DPI behavior. Those checks remain manual. x86/ARM64
WinUI, VB WinUI, .NET 11 and standalone Blazor are not advertised.

The subsequent commit changes compact prompt rendering only. Its CLI tests and
terminal checks pass; the provider/generated-source content is unchanged from
the successful Windows matrix. Its automatic matrix rerun is tracked on the PR.
